# encrypted-storage Specification

## Purpose

定义照片在离开客户端前受到加密保护、以分块密文存入私有仓库并在客户端解密使用的行为边界，同时区分应用不设置容量配额的要求与外部仓库平台实际存在的运行限制。

## Requirements

### Requirement: 上传前完成客户端加密

应用 SHALL 在任何照片内容上传至所选仓库之前完成客户端加密，仓库接收的是加密照片副本；具体算法、密钥层次、密码派生和格式尚待选型。

#### Scenario: 上传一张原照片
- **WHEN** 应用准备将本地原照片上传至 GitHub 或 Gitee 私有仓库
- **THEN** 原照片先在客户端经过加密处理
- **AND** 照片明文不会作为该同步流程的上传内容发送到仓库

### Requirement: 密文分块

应用 SHALL 将待同步密文组织为可分别传输的数据块，目标尽量控制在每块 50 MB 以内；单位、默认块大小、认证开销、例外及处理方式尚待细化。

#### Scenario: 大文件需要拆分
- **WHEN** 一份待同步密文大于目标块大小
- **THEN** 同步准备流程对它进行分块
- **AND** 以尽量保持各块在 50 MB 以内为目标，而非把整个照片库强制作为一个大文件上传

### Requirement: 应用不设置总容量配额

应用 SHALL 不因产品自行设定的照片库总容量配额拒绝导入或同步；这一要求不取消所选平台或本机的实际限制。

#### Scenario: 照片库持续增长
- **WHEN** 用户继续添加照片，且当前平台和本机条件允许处理
- **THEN** 应用不以自定的照片库总容量上限拒绝处理这些照片

### Requirement: 在客户端解密仓库副本

应用 SHALL 在用户通过照片库解锁条件后，在客户端解密仓库中的照片副本以供查看或导出。

#### Scenario: 查看已同步照片
- **WHEN** 客户端获取仓库密文且用户已满足照片库解锁条件
- **THEN** 应用在客户端完成解密后提供照片内容
- **AND** 不要求 GitHub 或 Gitee 接收照片解密密码来替用户解密

# Local Metadata Design

## Status

2026-11-09 用户已授权按序开发，并明确批准 security-foundation-review.md（SFR-1）的 TD01–TD06。本文 Proposed 部分的密码／密钥／锁语义以已批准 SFR-1 为准；SQLCipher 正式数据库接入仍待 TD07。旧任务编号见 previous-task-baseline.md 和 implementation-status.md，不能以安全选型批准替代实际持久化验收。

2026-11-09 用户新增明确要求：**本机元数据也必须加密，先设计**。原来提出的普通 SQLite 明文目录方案未获接受，不予实施。用户同时批准 `media_kit` 作为播放候选进行接入和验证。

用户随后同意先验证 SQLCipher 的 Windows／iOS 兼容性、事务恢复和临时文件保护，并确认三天周期内允许系统安全存储辅助解锁，重启后仍需四位应用锁。密码派生及平台密钥保护方案已随 SFR-1 批准，具体数据库发行版与正式接入仍待 TD07。Windows 来源预览只使用内存；关闭后的目录补扫及整理状态恢复仍未完成。

## Confirmed Scope

需要保护的本机落盘信息包括：来源目录和原文件名、媒体引用、相册名称与成员、收藏与隐藏设置、来源相册观察记录和代次、停止跟踪及 App 成员覆盖、同步请求和副本记录。索引备份、日志和数据库临时文件不能形成明文旁路。

Windows 来源原照片仍保留普通文件，这是已有确定需求；本机元数据加密不改变原照片目录的这一约定。四位 PIN 只承担应用锁，不能直接作为数据库加密密钥或代替三天照片密码复验。

本轮实际观察到 Windows 系统目录选择器在新进程中仍记住上次测试目录。App 不创建明文索引，并不等于操作系统没有产生选择历史；数据库加密不能覆盖系统维护的这些记录。正式隐私验收还需检查目录选择器的历史策略、系统缩略图与崩溃记录边界，不能将当前内存预览宣传为“本机没有任何明文元数据痕迹”。不会为消除系统历史而擅自清理用户记录或修改系统隐私设置。

## Candidate Comparison

| 候选 | 事务与维护 | 需要验证的边界 |
| --- | --- | --- |
| SQLCipher 加密数据库（已批准验证） | 沿用 SQLite 事务和查询，避免自行设计大型目录存储协议 | 两端原生构建、Flutter 绑定与许可证；主库、WAL、回滚日志和临时存储的加密配置 |
| 认证加密的完整目录快照 | 依赖较少，但每次修改需写新快照，规模增大时成本明显 | 崩溃切换、并发、版本迁移、重放／损坏检测，需要额外设计并验证 |

普通 SQLite 加几个加密字段不作为本轮推荐方案：索引、关系、路径、事务日志及临时排序仍容易遗漏。SQLCipher 只加入独立验证包，未接入正式 App。Windows 11 项基础检查与 10 个强制进程恢复场景通过，iOS 二进制预检及测试工程已准备，实际 iOS 构建／运行仍缺；详见 `sqlcipher-validation.md`。

## Proposed Key Boundary

1. 使用随机生成的本地目录数据密钥保护数据库；用户继续记忆照片解密密码，不新增要手工保管的密钥文件。
2. 按 SFR-1：照片密码经 Argon2id 派生后认证包装随机库主密钥；主密钥的用途 3 子密钥再认证包装独立随机目录密钥，避免把 PIN、原始密码或主密钥直接复用为数据库密钥。本机最小引导记录的实现见 credential-bootstrap-implementation.md，不等于数据库接入。
3. 已确认允许在三天周期内使用系统安全存储辅助解锁，重启仍须四位应用锁。辅助解锁、输入 PIN 或重启均不能延长周期；只有正确输入照片解密密码才开始新的三天周期。具体材料、平台 API、撤销和时钟规则按 SFR-1；实际平台适配在 1.4–1.6 验收，不写入明文密码、原始密钥或可绕过复验的开关。
4. 到期时停止目录访问、来源扫描、媒体播放及同步；正确照片密码验证后才重建所需会话。普通 PIN 锁同样暂停同步及来源读取，按用户明确批准的 SFR-1 TD06 执行。
5. 修改照片密码和遗忘行为按 SFR-1 的 TD05，在 1.7 实现；完整密钥轮换不自动加入。不通过“重置演示数据”修复真实数据库。

## Proposed Transactions and Recovery

- 将旧关联结束、新相册建立、系统观察名称推进以及导入代次写入同一事务；事务提交之后才发布新的 UI 状态。
- 来源路径、相册 ID、媒体版本、覆盖集合及停止记录均在加密表内；持久化适配器只接收结构化目录，不接收演示凭据。
- 首次创建时验证使用的确为加密后端，设置密钥后再进行数据库操作。错误密码、损坏、版本过新分别报告，不自动创建空库覆盖旧库。
- 禁用明文文件型临时存储；检查主文件及 WAL／journal／迁移备份的写入行为。仅把扩展名改为 `.enc` 或对主文件做字符串检查不能作为加密验收。
- 崩溃恢复保留最后成功提交的状态，不产生重复代次，不解除用户停止跟踪或成员覆盖。
- 播放封面与解密暂存单独管理；当前本机预览不把封面写入磁盘。未来需要暂存时必须进入同一隐私审核，不能存到未保护的缓存目录后声称本机数据均已加密。

## Confirmed Decisions and Remaining Design

- 已获准：先验证 SQLCipher，两端原生库、事务恢复、临时文件及许可均需记录；测试依赖不代表正式选型。
- 已确认：三天周期内允许系统安全存储辅助解锁，重启仍需四位应用锁；到期须正确输入照片密码，期间暂停访问及同步。
- 已由 SFR-1 批准：照片密码派生、随机目录密钥的包装、Windows／iOS 安全存储、期限与时间异常及密码修改／遗忘处理；相关平台实际验证尚待执行。本文旧候选措辞由该批准记录接续，不重新视为未定。

既有 SQLCipher 验证授权保留，按顺序在新任务 2.1 补齐双端验证和正式方案审核，再开展 2.2 的 App 接入；本次 1.1／1.2 没有重新运行 SQLCipher 探针。2.3–2.6、5.3、6.4–6.7 的正式持久化及跨启动验收不能以探针或会话预览替代。

## Verification Plan

- 使用人工生成的敏感标记作为路径／文件名／相册名，检查数据库、WAL、journal、日志、临时目录及备份不存在明文副本。
- 验证正确和错误密码、PIN 无法替代照片密码、到期阻断、内存中失效回调、锁定与恢复。
- 在系统相册改名事务的提交前后注入中断，重新打开后只出现一个正确的新代次；停止跟踪、App 加入／移出覆盖不丢失。
- 以大目录和大视频验证内存、事务延迟和崩溃恢复；不把无容量配额解释为可无限消耗内存。
- 在两端实际验证后再实施正式持久化与启动补扫。

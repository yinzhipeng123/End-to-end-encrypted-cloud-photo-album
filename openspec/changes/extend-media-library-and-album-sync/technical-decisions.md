## TD01 — 媒体认证加密构造

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| AES-256-GCM，由成熟实现提供 | 可使用已有标准化构造和实现；可核对测试向量 | 必须设计同一密钥下 nonce 唯一性、消息数量及大小界限；具体库的硬件依赖与两端性能需验证 |
| XChaCha20-Poly1305，由成熟实现提供 | 较长 nonce 可支持随机 nonce 方案，便于独立资源组织 | 需验证 Flutter 绑定、原生依赖、维护和格式互操作；不能因此省略随机数、版本绑定和完整性设计 |

待批：构造、库／版本、nonce 和资源版本规则、认证关联数据、错误行为。候选来自 R1；不自行实现密码学算法，不将 SQLCipher 内部算法自动当作媒体格式选择。验收 AC03。

## TD02 — 照片密码派生与参数

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| Argon2id | 内存困难函数，可根据端侧资源测量参数 | 内存、耗时、并发与低资源设备需实测；不得盲用示例参数 |
| PBKDF2-HMAC 系列 | 可利用现有密码学实现，参数结构较简单 | 需评估密码猜测成本；不能只选择“运行最快”的迭代数 |

待批：算法、盐、参数上下限、版本升级、密码编码／规范化及错误输入处理。正确密码原文不得持久化；数据库内部 KDF 与用户密码保护媒体密钥的 KDF 不是同一个决策。参考 R2/R3；AC02/03。

## TD03 — 内部密钥层次与密码变更

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| 随机库主密钥，由密码派生材料保护；目录／媒体用途分离 | 用户改密码可重新保护主密钥而不必重加密全部媒体 | 主密钥包装、版本、同步更新和历史包装副本管理复杂；改密码不自动撤销旧副本访问 |
| 随机目录密钥及逐媒体资源密钥，各自经已批准层次保护 | 可细分损坏影响与资源生命周期 | 包装记录更多，恢复、轮换和原子发布更复杂 |

待批：密钥生成／包装／用途隔离、仓库需携带的加密恢复材料、本机辅助材料及格式版本。用户仍只记照片密码，不新增必需手工密钥。不得把 PIN 或密码文本当数据密钥；AC02/03/11。

## TD04 — 系统安全存储与重启辅助解锁

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| 原生适配 Windows 用户范围保护与 iOS Keychain | 可直接控制平台属性和错误处理 | 两套原生接口维护；须验证用户绑定、设备迁移、可访问时机及凭据失效 |
| 经过审查的 Flutter 安全存储插件封装相同平台能力 | 减少桥接代码 | 必须核对实际后端和默认属性，不能只凭包名承诺安全；升级可能改变行为 |

待批：具体 API／插件版本、保存何种受保护材料、生命周期、卸载／账号变化／系统材料丢失的处理。三天内辅助解锁、重启 PIN 和到期强制照片密码均已定；插件不负责替 App 自动实现三天规则。威胁模型须写清同一已解锁系统用户及运行进程被攻陷后的边界，不能把四位 PIN 宣称为完整磁盘保护。平台事实按 R8/R9 后续核验；AC04/05/07。

## TD05 — 密码强度、遗忘与修改

| 子项 | 选项与收益 | 代价／安全影响 |
| --- | --- | --- |
| 强度规则 | 最小长度＋清晰提示；或强度估计＋最低阈值 | 前者易实现但覆盖有限；后者需选择和验证估计器。具体阈值待批，不能预置通用密码 |
| 遗忘照片密码 | 不提供解密恢复；或允许在具备获准解锁材料的设备上经规定验证更换 | 前者有永久失去访问风险；后者增加绕过强制记忆验证的风险，必须单独批准，不能默认启用 |
| 修改照片密码 | 对现有密钥重新包装；或轮换相关密钥并重新加密 | 前者成本较低但旧包装／历史材料需处理；后者耗时且中断恢复复杂 |
| PIN 遗忘 | 用正确照片密码重设；或仅提供明确的本机重新配置流程 | 前者需验证凭据与状态变更原子性；后者不能删除原媒体、仓库或绕过三天复验 |

这些是处理策略候选，不擅自新增密码找回、邮箱恢复、托管解密或恢复码产品功能。AC02/04/24。

## TD06 — 应用锁、复验时钟与在途工作

| 子项 | 选项 | 优缺点及安全影响 |
| --- | --- | --- |
| 普通锁触发 | 手动＋重启；增加失焦／进入后台锁定 | 前者打扰少但窗口暴露时间长；后者保护更及时但切换操作频繁。触发时机需批准 |
| 普通 PIN 锁与同步 | 继续已获准加密同步；暂停同步 | 前者减少等待但需保持有限工作材料；后者边界简单但影响自动同步。两者都必须停止媒体观看 |
| PIN 重试限制 | 延迟递增；达到阈值后要求照片密码 | 都需持久化关键限制并处理重启；不默认启用删库或清除原图 |
| 三天周期范围 | 各设备独立；跨设备共享经认证状态 | 独立不依赖联网；共享体验统一但离线合并和恶意回退复杂 |
| 时间异常 | 本机受保护记录＋单调时间辅助，异常时要求复验；增加可信时间参照 | 前者有离线恢复边界；后者引入联网依赖和隐私成本。不能用重启重新计时 |
| 到期的在途请求 | 尽力取消并核对远端；停止新发送，记录无法撤回的已发送部分 | 两者都不能撤回已到达服务端的字节；须明确本机阻断点及恢复核对，不能显示到期后仍可主动推进上传 |

三天从正确输入照片密码开始，到期暂停访问与同步已定；不得将“在途请求”作为继续新工作的例外。具体边界、错误路径与时间单位须随本决策批准；AC04/05/10。

## TD07 — 本机加密持久化

| 选项 | 优点 | 缺点与安全影响 |

## TD08 — 两个平台的真实授权与令牌

2026-11-10 最新边界：GAR-2（repository-authorization-review.md）的 GitHub App 单仓库安装、最小权限、Device Flow 用户令牌及 DPAPI／刷新处理已批准；用户随后授权协助注册并提供公开标识，真实设备码接口验证通过。RAR-1 TD09-A 与 GitHub 独立推进亦已批准；用户手动确认真实授权成功并提示未安装；安装与完整平台矩阵尚未验收，远端写入未授权。Gitee 必须无需自建服务；下表中授权中介为历史比较，不得据此新增服务。

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| 平台实际支持的公开客户端流程，如设备流程或满足平台要求的浏览器授权 | 可减少自建服务；用户在平台界面授权 | 每个平台需独立证明公开客户端可行性、回调／state／PKCE（适用时）、权限与令牌周期；不能把客户端包当作能保密 client_secret 的环境 |
| 需要机密客户端时，经用户批准的最小授权中介完成交换 | 可以在服务端保护客户端机密 | 新增托管、运维、令牌处理和信任边界；属于待单独批准的附加架构，当前不创建服务 |

GitHub App 的设备交换及其令牌刷新已有无需 secret 的官方参数证据；网页流程仍不能由 PKCE 推导无需 secret。Gitee 官方页面引用的脚本及中文正文现已读取，授权码交换明确包含 client_secret，尚未查到可确认的公开客户端／PKCE／设备授权链路；本次结果及来源以 GAR-2 为准。实际注册与平台验收均未完成。

GitHub 应用类型、最小权限、令牌保护、刷新及撤销边界已按 GAR-2 批准；Gitee 对应方案仍待能力证据与确认。不能悄悄以手工 PAT 输入替代已确认的授权登录。首次只选择用户明确的目标私有仓库；多仓库同时备份／自动建库不自动加入。AC08/09。

## TD09 — 仓库存储与提交协议

后续批准（2026-11-10）：用户明确批准 RAR-1 TD09-A，允许先实施阶段三 GitHub 授权与目标选择；Gitee 方案保留未完成，TD10／TD11 及实际远端媒体格式不因此获批。

2026-11-10：生效方案见 repository-storage-review.md（RAR-1）。TD09-A 使用 GitHub HTTPS API、固定版本、真实目标校验及 Git Database 非强制发布；第三阶段仅授权／选择，正式格式继续等待 TD10／TD11。Gitee 官方 OpenAPI 已单独核对，不能假定具备相同写接口；TD09-B 保留，不据此实现上传或改变删除策略。

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| HTTPS 仓库 API，上传对象后发布一致清单／版本 | 可与 App 任务和错误状态直接集成，免完整工作区 | 两个平台 API 不同；对象大小、请求频率、并发引用更新和部分提交必须实测 |

## TD10 — 密文格式、分块和元数据范围

2026-11-10后续：用户已明确批准WSR-1 TD10-S／TD11-S、TD13-S／TD12-S及TD09-I，具体格式／参数、恢复与冲突、调度／暂存及空库例外以windows-sync-review.md为准。以下选项表作为历史比较；未纳入的导出／删除／Gitee方案仍待确认，不能把设计批准计为已实现。

| 子项 | 选项 | 优缺点及安全影响 |
| --- | --- | --- |
| 分块组织 | 每块独立认证并以完整清单绑定；流式加密后按可恢复边界传输 | 前者易重试／随机访问但清单复杂；后者顺序处理简单但定位与断点需额外设计。都要防丢块／替换／重排／截断 |
| 50 MB 的准确单位 | 十进制字节；二进制 MiB 且明确修订单位 | 会改变真实上限；必须计算头部和认证开销，不能只检查原文件大小或显示块数 |
| 远端元数据 | 加密资源清单＋最少公开格式头；进一步隐藏名称／关系／大小信息 | 前者结构较简单但数量／大小可见；后者流量、填充和维护成本更高。须明确机密字段及允许泄露项 |
| 格式升级 | 保留旧版本读取、显式迁移；仅允许受控升级后读取 | 前者维护成本高；后者可能使旧客户端不可用，必须保留原数据并准确报错 |

待批：块尺寸、硬限制／例外及平台拒绝时处理、认证开销、资源 ID 与顺序、版本和尾部完整性、解密随机访问策略。备份始终保留原始视频及 Live Photo 必要资源，禁止以转码降低质量替代。AC03/10/11。

## TD11 — 媒体身份、并发和同步恢复

2026-11-10：用户已明确批准 WIR-1 的 TD11-W，采用其中 B 方案和完整细则；原生身份、改名／同卷移动、独立副本、保守降级及 BLAKE2b-256 仅限本机加密索引。远端／跨设备身份、并发和删除记录不纳入本次批准，真实接入及验证见 windows-import-implementation.md。

| 子项 | 选项 | 优缺点及安全影响 |
| --- | --- | --- |

| 中断任务 | 持久化逐资源确认点；重启重新核对远端状态 | 前者接续快但本机记录可能落后；后者请求更多。都必须校验实际远端结果且避免重复发布 |

待批：跨设备身份、冲突规则、变更版本、去重和删除记录协议。已确认同目标同版本请求合并、换仓库不得继承成功、删除远端后仅显式重传；不得用新的去重策略推翻这些行为。AC10/12/23。

## TD12 — 导出目标与暂存

| 子项 | 选项 | 优缺点及安全影响 |
| --- | --- | --- |
| Windows 导出冲突 | 用户选择新名称；明确确认覆盖 | 前者避免覆盖但增加文件；后者简洁但必须确认具体目标，取消无副作用 |

待批：默认目的地、原始资源完整输出、同名行为、取消／磁盘满的半成品清理，及明确批准的明文导出目标与内部缓存边界。用户主动导出普通文件不等于允许 App 将敏感索引／内部暂存明文落盘。AC20/24/25。

## TD13 — 自动同步运行条件与资源界限

2026-11-10：用户已明确批准 WIR-1 的 TD13-W，采用其中 B 方案和完整细则：稳定只读句柄、事件合并／补扫、分批资源预算、重试与取消边界。Windows 实际接入及证据见 windows-import-implementation.md；网络调度及 iOS 后台方案仍保留原未决范围。

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| 前台／进程可运行时调度，恢复和重启补扫 | 与已确认导入预期一致，运行状态易观察 | 不提供退出后持续同步；仍需确定事件合并、批大小、重试节奏 |
| 增加平台允许的后台任务／Windows 常驻组件 | 可覆盖更多不在前台的场景 | 平台限制、耗电、权限和运行材料生命周期更复杂；常驻或附加组件需要独立批准 |

待批：网络条件、暂停恢复、扫描延迟目标、最大并发、峰值内存／磁盘预算及大文件读取稳定性验收。应用不设照片库容量配额不等于不设运行资源界限；不承诺 iOS 进程终止后继续执行。AC10/13/14/22。

## TD14 — 删除策略与恢复边界

| 子项 | 选项 | 优缺点及安全影响 |
| --- | --- | --- |
| Windows 原文件删除 | 系统回收；明确永久删除 | 前者可恢复但须验证路径／卷实际支持；后者释放直接但不可误触，失败不能伪报 |
| 删除本地前的仓库验证 | 必须验证完整可恢复；允许用户明确承担无备份删除 | 前者较安全但增加等待；后者更灵活但可能丢失唯一副本。Q08 尚未确认 |
| 远端历史处理 | 删除当前有效副本并准确说明范围；另行批准历史重写／清理 | 前者保留历史可能继续占空间；后者涉及并发、权限、历史引用及不可逆影响，不能静默执行 |
| 离线设备同步删除 | 持久化删除操作，逐设备确认；需要再次确认后删除离线设备原文件 | 前者自动化强但须处理过期客户端；后者更审慎但改变完成时机，必须先确认 |
| 半完成删除 | 保留逐目标结果并重试；尝试有条件补偿 | 前者真实可追踪但存在部分完成；后者不能保证已删除原图可恢复，不能承诺跨设备原子回滚 |

iPhone 必须使用实际系统原媒体操作并尊重用户取消／系统结果；系统回收行为与“永久清除”宣传须验证，不能擅自扩大删除。三种范围、外部 Windows 原图消失保留仓库、App 相册删除不删媒体、显式重传规则均已定。AC21/23/24。

## TD15 — 双端媒体能力与依赖

| 选项 | 优点 | 缺点与安全影响 |
| --- | --- | --- |
| 继续验证已获准的 media_kit 及兼容原生构建 | 可复用现有接口与已完成局部能力 | 当前 ProRes 人工样本失败；依赖发行、许可、升级和真实 iPhone 样本仍需验证 |

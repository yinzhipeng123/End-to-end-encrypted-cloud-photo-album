## TD07 Windows Proposal — Approved

建议沿用已经隔离验证的 `sqlite3 3.9.1` 绑定，通过 native assets 的 `source: sqlcipher` 选择 SQLCipher。Windows 产物须匹配已验证 SHA-256 `f13740c540bc2fd35c52372bf6effcaaf488b09e81c11d1896ac61b6cab06dce`，记录实际 `cipher_version` 和 provider；不允许普通 SQLite 降级。

- 使用 SFR-1 已批准的独立随机 32 字节目录密钥；照片密码保护主密钥，PIN 只控制门禁，不作为数据库密钥。
- 每个连接在查询前设置密钥，检查真实加密后端、读取页面及版本；错误密钥、损坏、未知版本均保留旧库并报错，不创建空库覆盖。
- 初版使用 DELETE 回滚日志、`synchronous=FULL`、`temp_store=MEMORY`、`cipher_memory_security=ON`、外键检查；不启用明文头部，不输出含密钥的 SQL 或原始数据库异常。
- 所有目录变更在事务中提交；未知版本只读拒绝，迁移须在加密事务或独立加密目标中完成。阶段二验证进程中断、写入失败、日志／临时文件和实际 App 重开。
- 普通锁／期限失效撤销会话并关闭目录连接；系统保护材料仍按批准 DPAPI 方案处理。当前 Windows 接入批准不表示 iOS 打包或平台验收完成。
- 保留 Dart 绑定、SQLCipher Community 和其 Windows 加密后端的许可告知；发布包核对原生库身份。既有探针结果仅作为选型依据，正式接入仍须独立测试。

替代方案是自行实现认证加密快照／日志；需要额外设计查询、事务、迁移和崩溃恢复，当前不建议替代已有可验证后端。普通明文 SQLite 仍被排除。

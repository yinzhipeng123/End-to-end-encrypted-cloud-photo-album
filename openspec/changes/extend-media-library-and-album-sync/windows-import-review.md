## Confirmed Scope

- 用户选择 Windows 本机目录，包含全部实际子目录；解锁且 App 运行时发现新增，下次启动解锁后补扫。
- 原始照片和视频仍在原位置，内容、名称和目录结构保持原样。导入是管理原文件，不自动复制另一份原文件到程序数据目录。
- 来源、文件名、路径、媒体属性、版本和扫描记录进入现有 SQLCipher；不新增明文清单、SQLite 旁路或日志中的媒体路径。
- 同一来源重复事件不重复建项；完整扫描后确认的原文件消失只改变本地可用性，不删除仓库、不丢失整理状态。
- 取消选择无记录；目录、权限或读取失败准确反馈，已提交记录保留。成功提交后重启可恢复，不能把内存预览称为导入完成。
- 普通锁与 72 小时到期都撤销导入访问。文件名仅详情显示，卡片不生成标题；修改时间不能冒充拍摄时间。
- 视频、Live Photo、H.264／HEVC／ProRes 和既有完整播放验收要求不变。局部导入交付不意味着全部播放、上传、相册整理或整个阶段五完成。

## TD11-W — Local Source Identity and Version

本节只决定 Windows 本机来源身份和内容版本；**不决定**跨设备身份、远端清单、并发合并、删除协议或跨文件内容去重。

### Options

| 选项 | 用户可见行为 | 代价与安全影响 |
| --- | --- | --- |
| A：规范路径为身份 | 同一路径不重复；改名／移动通常产生新项目 | 简单，但整理状态难以随同卷移动保留，同路径替换容易误关联 |
| B：原生文件身份＋随机 App ID，必要时明确降级（建议） | 能确认同一原文件时保留项目与整理；不同副本分别管理 | 要处理文件 ID 复用、文件系统差异和不确定情况，不能将系统 ID 当密码学身份 |
| C：按完整内容指纹全库合并 | 相同字节的独立副本可能只显示一个项目 | 引入多来源删除和重复合并语义，可能合并用户有意保留的副本；当前没有此项产品批准 |

### Proposed Behavior

建议选择 B，具体规则如下，均已获本稿批准：

1. App 媒体 ID 使用现有安全随机源生成的 128 位随机值；路径和指纹都不是主键，也不用于推导加密密钥或 nonce。
2. 能取得可靠原生身份时，使用卷身份、`FILE_ID_INFO` 的 128 位文件 ID 和创建信息定位本机原文件，保留实际路径引用。文件 ID 是文件系统提供的观察值，不能证明跨删除、跨卷或恶意篡改后的永久身份。[R1/R2]
3. 同卷改名／移动且仍落在已选择范围内、原生身份和创建信息一致时更新引用，保留原媒体 ID 和整理。跨盘移动、独立复制、同路径替换而原生身份不同，建立新项目；不按文件名或相同内容自动合并。旧项目的本地缺失、已有副本和整理记录保留。
4. 重叠选择目录不重复建项；同一原生文件的硬链接保留多个来源引用，一个逻辑项目。任一可读引用存在时不能把整个项目标为本地缺失；这不批准未来的硬链接删除操作。
5. 原生身份不受支持、出现冲突或创建信息异常时，不猜测移动关系。降级为“规范路径＋创建信息＋已核对内容版本”的保守来源匹配，界面说明该来源不能可靠跟踪改名。相同路径及核对信息完全相同才复用；不能确认时建立新项目，旧项目保留，不能继承旧副本成功。路径匹配尊重目录的大小写语义，不能统一转小写导致不同文件合并。
6. 已明确观察到删除后重新出现的身份，不仅凭旧 ID 自动复活；按新来源处理。未观察到的删除及 ID 复用仍是平台边界，创建信息只能辅助，不能声称彻底消除复用风险。导入身份匹配永远不授权删除原文件或认定备份完成。
7. 内容版本建议用现有 `sodium 4.1.2+1`／已固定原生 libsodium 的流式 BLAKE2b、32 字节输出、无 key，对**完整原始字节**计算；同时记录字节数及算法版本。摘要只存 SQLCipher，不写仓库公开字段、文件名或日志，不承担消息认证或密码派生职责。[R3]
8. 首次、来源事件标记变化、属性变化或需要重新核对时执行完整读取。size／mtime 仅作调度提示，不能证明字节未变；沿用旧记录时只保留“上次验证版本”，不声称刚验证了内容。未来上传必须在真实读出时重新验证版本，不能直接凭导入记录认定当前原文件或远端副本完整。
9. 对可靠同一来源的内容变化建立新资源版本，保留媒体整理，旧版本备份状态不能套用到新版本；保留“删除仓库副本后禁止自动重传”的用户意图，不由扫描解除。不可靠降级来源不能确认连续性时按第 5 项处理，不暗中合并。

完整内容读取增加首轮耗时；加密数据库保护摘要静态存储，但摘要一旦泄露仍可能用于已知内容比对。这里不新增密钥，也不改变 SFR-1 的加密算法。

## TD13-W — Stable Reading and Scheduling

### Options

| 选项 | 优点 | 代价与安全影响 |
| --- | --- | --- |
| A：两次大小／修改时间不变后直接读 | 对其他程序干扰较少 | 复制暂停后还可能追加，读取中也可能混入不同版本；不能单独作为完整性依据 |
| B：安静观察＋持有拒绝写入／删除的只读句柄，完整流读并核对（建议） | 能拒绝活动写入，降低读取中变化；不复制完整大文件 | 读取期间其他程序可能暂时无法写入、改名或移动这个文件；必须可取消 |
| C：先复制完整暂存再处理 | 后续可基于独立副本工作 | 需要额外磁盘、暂存保护与恢复设计，复制过程本身仍要解决一致性；当前不新增此路线 |

### Proposed Behavior

建议选择 B，具体规则如下，均已获本稿批准：

1. 发现候选后观察至少 2 秒无已知变化；该等待只是降低无效尝试，不是完整性证明。随后 `CreateFileW(OPEN_EXISTING, GENERIC_READ, FILE_SHARE_READ)` 打开真实文件，拒绝写共享和删除共享，保持同一个句柄到读完和提交核对结束。不修改源文件的权限或属性。[R4]
2. 已有写句柄、可写映射或不兼容共享状态导致打开失败时，保留“文件使用中，稍后重试”，不标已导入完成。持有句柄时新写入、改名／移动可能被系统拒绝；这是该方案需要用户确认的实际影响。[R4]
3. 从同一句柄获取原生身份、大小、创建及修改信息，分块读到实际 EOF，计算摘要；实际字节数与前后属性／身份须一致。读取失败、属性变化、源失联、取消或会话失效时丢弃本次未提交候选，保留上次已提交记录。
4. 只读完整快照不证明文件格式完好，也不能证明写入者以后不会重新打开继续追加。候选发现、字节快照完成、格式识别、缩略图／解码可用及远端备份状态分开记录。零字节、扩展名伪装、容器截断／损坏或后端不能解码须准确反馈，不伪造封面或播放成功；后续变化重试。
5. 原始媒体识别和属性读取尽可能使用同一受控资源；若现有媒体后端只能按路径重开，必须在保持原句柄、核对实际目标和会话有效的边界内执行，并验证关闭行为。不能因扩展名是 MOV 就推断 ProRes 或 Live Photo；可靠配对与全格式验收仍属 5.7–5.9。
6. 只在 App 运行且访问已解锁时调度，不新增常驻进程。解锁先恢复加密来源记录，建立监听并补扫；事件只作为“需要核对”的提示，不能直接按删除事件删除媒体。监听结束／错误时重新建立并安排补扫，启动与定时扫描补偿漏事件。[R5]
7. 初始可验证预算：全局 1 个内容读取工作项；单次读取块不超过 1 MiB；待处理候选内存上限 128 条，超出进行背压／持久化调度；每次加密事务最多 100 条；界面按最多 200 项分页。队列和列表不全量载入全部媒体，原文件不整份读入内存，也不创建完整明文暂存。这里不是媒体总容量限制。
8. 事件合并等待 1 秒并设 5 秒最长延迟，避免事件持续到来导致永远不处理；每次完整枚举完成后 60 秒安排下一次补扫，同一来源不并发枚举。工作占用时合并请求，不无限排重扫。读写冲突／临时不可访问按 5、15、60 秒退避，之后每 60 秒重试；具体计时在解锁运行期间生效。大库只承诺持续推进和真实进度，不宣称所有文件在固定秒数内导入完成。
9. 候选观察、待处理与最近已验证结果均有明确状态；收到事件或元数据扫描时不必对全库每分钟重新哈希。异常停止后重新核对来源，已完成事务保留，当前未提交版本重做；不依赖明文扫描检查点。
10. 一次扫描只有在完整遍历且未遇到权限、读取、源失联等未解决问题时，才用于判定该来源缺失引用。部分成功仍可逐批保存新发现项目，但失败子树不能被解释成删除。已确认文件缺失也不删除媒体记录或仓库副本。
11. 实际子目录均递归；符号链接、目录联接和重解析点不当作可任意跟随的子目录，防循环及越出授权根。必须显式报告未遍历入口，不能显示整个来源扫描完整；不能为了读取而自动扩展用户选择范围或触发脱机占位文件下载。实现时校验打开后的实际位置，避免先检查路径再被替换的竞态。
12. 锁定先撤销代次、拒绝新读取和提交，取消监听／调度与在途读取，关闭句柄和控制中的媒体资源，清理可控缓冲区和视图。不得只隐藏窗口而让工作继续；迟到结果不能写库或显示。验证真实取消延迟与资源释放；无法实现此边界时保留未完成，不以未取消的大文件读取作为默认例外。

# Spec Delta

## MODIFIED Requirements

### Requirement: 自动同步照片

应用 SHALL 提供照片、Live Photos 和独立视频的自动同步能力，将符合当前访问及同步条件的媒体通过客户端加密流程同步到所选私有仓库；Windows目录发现遵守windows-media-import，Windows GitHub按WSR-1和WBL-1在进程已解锁建立有效后台会话后调度，最小化／手动界面锁不停止后台，iOS相册来源关系遵守ios-album-import，iOS后台规则仍待验证。

#### Scenario: 有照片等待同步
- **WHEN** 客户端发现待同步照片且当前访问条件允许执行同步
- **THEN** 应用自动将照片纳入同步处理
- **AND** 上传前必须满足 encrypted-storage 的客户端加密要求

#### Scenario: 有视频或实况照片等待同步
- **WHEN** 客户端发现符合条件的待同步独立视频或 Live Photo
- **THEN** 该媒体项目进入加密同步流程
- **AND** Live Photo 只有所需资源整体完成后才报告该项目同步完成

## ADDED Requirements

### Requirement: 同步队列支持真实分页与安全重试
应用 MUST 按当前仓库显示持久化任务、分类数量与分页；重试只能推进符合当前来源和版本条件的失败任务，保留有效退避及显式删除决定，不覆盖冲突。

#### Scenario: 用户重试历史失败上传
- **WHEN** 用户点击失败或退避任务的重试按钮
- **THEN** 核验来源、版本和目标，保存真实重试意图；暂停及限流仍阻断执行
- **AND** 历史完成任务不冒充当前副本存在，冲突不能通过重试强制覆盖

### Requirement: 仅仓库目录跟随认证版本
应用 MUST 在当前仓库认证清单版本变化时更新同来源的仅仓库记录并失效旧封面，同时保留相册与收藏，不覆盖本地原文件。

#### Scenario: 已缓存封面的仅仓库项目出现新版本
- **WHEN** 读取并认证当前清单发现来源版本变化
- **THEN** 更新版本和属性，清除旧视图元数据，下一次查看读取新封面
- **AND** 保留原媒体整理身份；本地原文件继续按既有冲突规则处理

### Requirement: Windows 导出真实原始资源且不覆盖
Windows 客户端 SHALL 按 TD12-W 将所选媒体原始资源写入用户选择目录下的独立子目录，完整校验输出字节后使用不替换现有文件的发布操作；Live Photo 必须包含两个资源，部分失败不得计为整项成功。

#### Scenario: 导出中断或同名目标出现
- **WHEN** 导出发生取消、磁盘不足、进程终止或目标已存在
- **THEN** 保留真实结果与加密操作记录，不覆盖已有文件，不把部分资源计为完整导出
- **AND** 用户可查目的地与已完成部分，强制终止遗留的 partial 不被误报为最终文件

### Requirement: Windows 删除与恢复遵循 TD14-W
Windows 客户端 SHALL 提供原三种删除范围；本地原文件以经验证同句柄同卷移动到来源根目录 .epa-recycle 的方式移除，支持不覆盖的原位置恢复；远端以认证删除标记和非强制提交删除当前有效副本，不重写 Git 历史。操作状态加密持久化。

#### Scenario: 删除本地但保留仓库
- **WHEN** 用户选择只删除本地
- **THEN** 先真实读取、认证并完整校验当前仓库副本，再移除原路径
- **AND** 当前仓库副本不可恢复时拒绝移除，不仅依赖旧完成标记

#### Scenario: 删除仓库但保留本地
- **WHEN** 用户选择只删除仓库副本
- **THEN** 持有并核验当前完整本地资源，发布仓库删除及不自动重传意图
- **AND** 显式单项或批量上传可以重新建立仓库副本

#### Scenario: 离线客户端收到同步删除
- **WHEN** 客户端重连取得认证删除标记
- **THEN** 只对匹配的旧资源版本执行本机移除，内容变化则保留冲突
- **AND** 单机处理完成不表示全部离线设备已完成，不声称历史密文已擦除

#### Scenario: 中断恢复与重复删除
- **WHEN** 回收或恢复发生在文件移动后、数据库提交前中断，或恢复后的同版本再次被用户删除
- **THEN** 核对实际原位置和回收位置的完整字节再修复记录；新的删除使用新的操作身份
- **AND** 已恢复文件不被同一次历史删除重放，恢复不自动重建用户此前删除的仓库副本

### Requirement: 发布确认和冲突按WSR-1执行
Windows GitHub同步 SHALL 先加密并验证源版本、上传并读回核对完整资源，最后以非强制引用更新发布认证清单；只有实际发布读回完整才保存已备份状态，未知结果重启先核对。同媒体版本重复请求合并，冲突不静默覆盖。

#### Scenario: 发布请求超时但服务端可能已提交
- **WHEN** 本机未取得明确发布结果，随后恢复可访问条件
- **THEN** 核对实际分支、候选提交及认证清单，再决定接续或确认
- **AND** 不盲重发、强推或用定时器标成功

#### Scenario: 两端同时写入
- **WHEN** 非强制发布遇到竞争且远端头已变化
- **THEN** 重读并认证，不同媒体可合并，同媒体不同内容保留冲突并停止自动选主
- **AND** 恢复材料冲突不自动按代次大小覆盖

### Requirement: 单项媒体上传入口

应用 SHALL 在媒体卡片操作菜单的“查看详情”下方提供“上传”，将当前媒体加入所选 GitHub 或 Gitee 私有仓库的上传队列；用户可以在同步界面查看处理状态。

#### Scenario: 上传本地媒体
- **WHEN** 用户对有本地原文件且需要上传的照片、视频或 Live Photo 点击“上传”
- **THEN** 应用为该媒体请求当前目的仓库的上传任务
- **AND** 入队不等于已完成加密或已完成备份

#### Scenario: 无可用本地内容
- **WHEN** 用户尝试上传但对应媒体所需的本地原始资源不可读取
- **THEN** 应用说明无法执行的原因
- **AND** 不显示虚假的上传完成或仓库副本存在状态

### Requirement: 批量上传所选媒体

应用 SHALL 在选择模式提供“上传”，按 photo-library 确定的当前选择集合处理照片和视频，并分别反馈各项目的排队、处理和失败结果。

#### Scenario: 当前筛选结果全选后上传
- **WHEN** 用户全选当前搜索／筛选／相册结果并点击上传
- **THEN** 仅这些选中媒体进入上传处理
- **AND** 聚合视图中被隐藏的媒体不会被额外纳入

### Requirement: 删除仓库副本后允许显式重传

应用 SHALL 允许用户对曾执行“删除仓库副本，保留本地”的媒体进行单项或批量上传，从“仅保留本地”重新建立仓库副本；没有显式重传操作时，保留其删除后不自动重传的状态。

#### Scenario: 手动重新上传已删除远端副本的项目
- **WHEN** 仓库副本已删除而本地原文件仍可用，用户显式执行单项或批量上传
- **THEN** 对相应选中媒体重新执行加密上传流程
- **AND** 只有上传成功后才更新为已同步
- **AND** 未选中的“仅保留本地”项目不会因此自动重传

### Requirement: 手动上传共用同步阻断条件

应用 SHALL 使手动和批量上传遵守上传前加密、三天照片密码到期暂停以及其他必要运行条件；手动操作不能绕过密码验证或擅自解除已生效的同步暂停。

#### Scenario: 批量处理期间三天验证到期
- **WHEN** 三天照片密码验证到期且批量上传尚未全部完成
- **THEN** 未完成上传保持阻断，保留已完成结果和待处理工作
- **AND** 正确照片密码之外的操作不能使任务继续上传

#### Scenario: 验证成功但仍存在其他阻断
- **WHEN** 用户验证照片密码成功，但同步仍被网络、仓库权限或手动暂停阻断
- **THEN** 应用只解除照片密码导致的阻断
- **AND** 不把仍未上传的媒体报告为已同步

### Requirement: 重复触发不产生重复上传任务

应用 SHALL 对同一目的仓库、同一媒体版本合并重复的上传请求；已同步且内容未变化的项目不重复上传，已有任务不会因单项与批量入口交叉使用而重复创建。

#### Scenario: 上传过程中再次批量上传
- **WHEN** 已在上传的媒体又包含在用户提交的批量上传选择中
- **THEN** 继续原有任务，不建立同一内容的第二份上传任务
- **AND** 不重置其已完成进度

#### Scenario: 当前仓库已存在未变化副本
- **WHEN** 用户对已确认在当前仓库同步且未变化的媒体执行上传
- **THEN** 应用反馈已同步并跳过重复内容传输
- **AND** 不把其他仓库的同步状态当成当前仓库的完成状态

### Requirement: 同步结果由真实仓库确认
应用 SHALL 以真实资源处理、仓库写入及完整发布核对结果更新备份状态；实际进度不得由定时器或模拟状态产生，部分资源完成不能报告整个媒体已同步。

#### Scenario: 实际上传仅部分完成
- **WHEN** 某媒体只有部分密文块或必要资源成功上传
- **THEN** 应用显示真实已处理与未完成结果
- **AND** 不宣称该媒体已完整备份

### Requirement: 同步意图与任务跨启动保留
应用 SHALL 持久化上传意图、目标与版本、确认进度及必要删除／不自动重传状态，重启后核对实际仓库结果再继续；网络、权限、手动暂停和到期原因分别处理。

#### Scenario: 上传中退出并再次启动
- **WHEN** 上传尚未完成时客户端退出，之后重新打开并满足执行条件
- **THEN** 应用依据持久化记录和实际远端状态接续未完成工作
- **AND** 不重复发布已完成内容或把旧仓库结果带到新目标

#### Scenario: 删除远端后重启
- **WHEN** 用户已删除仓库副本保留本地且未显式重新上传，随后重启
- **THEN** 应用保留不自动重传决定
- **AND** 后续仅对用户显式选择的项目重新建立仓库副本

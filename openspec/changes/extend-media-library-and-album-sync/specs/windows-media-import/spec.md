# Spec Delta

## Purpose

让 Windows 用户选择已有照片目录后，将其中的照片和视频持续纳入 App 管理，通过运行期发现与启动补扫覆盖文件新增，并避免把外部源文件变化误解释为删除仓库备份的指令。

## ADDED Requirements

### Requirement: Windows 实况使用真实标识配对
Windows 客户端 SHALL 只在原始标签存在相同 Apple ContentIdentifier 且恰为一张静态图和一个动态视频时建立实况关联；关联、原资源身份和版本进入加密数据库，不凭文件名或相同字节猜测。列表使用静态资源封面，缺少任一必要资源不能报告完整本地副本。

#### Scenario: 配对歧义和资源缺失
- **WHEN** 同标识存在多个候选、标识缺失或已关联资源不可用
- **THEN** 不擅自匹配替代文件，分别保留原资源或准确标记原组合不完整
- **AND** 不新增模拟动态内容，不丢失既有整理记录

#### Scenario: 重复扫描已整理实况
- **WHEN** 实况已建立且用户调整过 App 相册成员后再次扫描
- **THEN** 沿用原组合身份，不重新继承旧组件成员来撤销用户调整

### Requirement: 选择目录递归发现媒体

Windows 客户端 SHALL 提供选择本机文件夹的导入入口，扫描所选目录及所有子目录，将支持的照片和视频纳入 App 管理；原目录保留普通原文件。

#### Scenario: 导入包含多层目录的照片与视频
- **WHEN** 用户选择一个包含照片、视频和多层子文件夹的目录
- **THEN** App 扫描根目录和全部可访问子目录中的支持媒体
- **AND** 不移动、改名、加密替换或删除原目录文件

#### Scenario: 取消目录选择
- **WHEN** 用户取消文件夹选择
- **THEN** 不增加导入来源或媒体记录

### Requirement: 运行期间发现新增媒体

Windows 客户端 SHALL 在 App 运行时持续发现已选择目录及其子目录内新增的照片和视频，并将其导入；重复观察同一来源文件不能重复建立相同媒体记录。

#### Scenario: 新增文件和子文件夹
- **WHEN** App 运行期间，所选目录中新建子文件夹并放入照片或视频
- **THEN** App 在该目录来源内发现并导入新增媒体
- **AND** 重复文件事件不会使相同来源媒体重复出现

### Requirement: 下次启动补扫遗漏

Windows 客户端 SHALL 保存已选择的导入来源，并在后续启动时补扫 App 关闭期间遗漏的新增媒体；补扫保留既有媒体的整理状态。

#### Scenario: 关闭期间新增媒体
- **WHEN** App 关闭期间来源目录增加媒体，用户随后重新启动 App 并满足访问条件
- **THEN** App 补扫并导入遗漏媒体
- **AND** 已导入媒体的收藏、相册归属和已有副本状态不因补扫重置

### Requirement: 外部源文件消失不删除仓库副本

Windows 客户端 SHALL 在原文件被外部删除或移走时标记本地原文件缺失，保留已有仓库副本；远端删除仍必须由既有明确删除操作触发。

#### Scenario: 文件管理器中删除已备份原文件
- **WHEN** 用户在 App 外删除或移走已备份的来源文件
- **THEN** App 标记对应本地原文件缺失
- **AND** 已有仓库副本不会因此进入删除任务

### Requirement: 导入结果与同步结果分别反馈

应用 SHALL 区分发现／导入媒体、等待加密上传和实际同步完成；目录不可访问或扫描失败不能被报告为成功导入，也不能直接被解释成原文件或仓库副本已删除。

#### Scenario: 目录暂时不可访问
- **WHEN** 某个已选择目录不可访问或扫描失败
- **THEN** App 显示该来源未完成扫描的状态
- **AND** 保留已有记录和仓库副本，待来源可访问后继续核对

#### Scenario: 已导入但未完成上传
- **WHEN** 媒体已加入 App 而加密上传尚未完成
- **THEN** App 不将它显示为已完成真实仓库备份

### Requirement: 真实来源与持久化导入结果
Windows 客户端 SHALL 依据实际目录和可读取资源建立媒体记录，并在批准的加密目录中保存导入来源及媒体状态；导入完成不能仅指建立本次进程内的预览列表。

#### Scenario: 真实目录导入后重启
- **WHEN** 用户选定目录且应用报告导入保存完成，随后重新启动并解锁
- **THEN** 应用恢复该来源及已提交媒体记录并进行补扫
- **AND** 不要求用户重新手动选择目录来冒充启动恢复

### Requirement: 变化中资源不得冒充完整导入
Windows 客户端 SHALL 按批准的稳定版本读取边界处理复制中或扫描后变化的文件，不能将不同版本的字节或不完整资源报告为完整可备份内容。

#### Scenario: 大视频仍在写入
- **WHEN** 来源大视频在发现或读取期间仍发生变化
- **THEN** 应用保留真实待处理或重试状态，并在满足稳定版本条件后处理
- **AND** 不把一次扩展名匹配或短暂大小不变直接当作备份完整性证明

### Requirement: 本机来源身份与版本遵循 WIR-1
Windows 客户端 SHALL 按用户于 2026-11-10 批准的 TD11-W 使用随机媒体 ID、原生卷／文件身份与创建信息确认同一来源，使用完整原始字节的 BLAKE2b-256 记录内容版本；路径与摘要仅存于加密索引，不用于推导密钥或认定远端备份完成。

#### Scenario: 同卷改名与独立副本
- **WHEN** 能可靠确认同一原文件改名或在已选择范围内同卷移动
- **THEN** 保留媒体 ID、收藏、相册及禁止自动重传意图，并更新来源引用
- **AND** 独立复制、跨卷副本或不同原生身份的同路径替换分别管理，不按相同字节合并

#### Scenario: 原生身份不足或已明确缺失
- **WHEN** 原生身份不可用或异常，或旧来源已经被完整扫描明确标记为缺失
- **THEN** 使用 WIR-1 的保守路径／创建信息／内容版本匹配；无法确认时新建项目，不继承旧副本完成状态
- **AND** 不仅凭再次出现的旧文件 ID 复活已明确缺失的项目，不能可靠跟踪改名时明确显示

#### Scenario: 重叠目录与硬链接
- **WHEN** 同一个原生文件由重叠根目录或多个硬链接被发现
- **THEN** 保留真实来源引用并复用一个媒体项目
- **AND** 任一可用引用仍存在时不把整个项目标为本地缺失；这不授权删除操作

### Requirement: 真实读取与加密提交保持同一受控资源
Windows 客户端 SHALL 按已批准 TD13-W 先观察至少 2 秒无已知变化，再持有拒绝写入与删除共享的只读文件句柄，读取完整字节并核对身份、属性与字节数；句柄保持到加密提交核对结束，按 WBL-1 仅强制安全锁撤销后台新读取／提交，最小化／手动界面锁保留导入，但撤销所有界面预览。

#### Scenario: 写入冲突或读取取消
- **WHEN** 活动写入导致打开失败，读取中版本发生变化，或访问会话被撤销
- **THEN** 不提交本次未完成媒体版本，不伪报成功，保留已提交记录并按批准退避重试
- **AND** 关闭受控句柄、清理受控预览缓冲，迟到回调不能重新写库或显示内容

#### Scenario: 链接或部分目录不可访问
- **WHEN** 来源含重解析点、目录联接、脱机占位内容或不可访问子树
- **THEN** 不跟随到授权目录外、不自动下载占位内容，明确显示该轮核对不完整
- **AND** 不能将不完整遍历用于清除缺失引用或删除仓库副本

### Requirement: 扫描调度和资源使用有界
Windows 客户端 SHALL 遵循 TD13-W 的单个内容读取、每块不超过 1 MiB、候选批次不超过 128 条、单次加密事务不超过 100 条和界面最多 200 项分页的预算。事件按 1 秒合并并设 5 秒最长等待，完整枚举后 60 秒补扫，暂时失败按 5／15／60 秒后每 60 秒退避；这些边界不构成照片库总容量配额。

#### Scenario: 队列大于单批上限
- **WHEN** 实际媒体数量超过内存候选或界面单页上限
- **THEN** 将来源与候选状态加密持久化，分批推进并通过分页访问已保存媒体
- **AND** 不将全部原文件或全部媒体队列一次载入内存，不因分页漏掉已提交记录

#### Scenario: 监听结束与重启恢复
- **WHEN** 监听结束、报错、遗漏事件或客户端重新启动解锁
- **THEN** 重建可用监听并核对加密保存的来源，补扫新增媒体
- **AND** 保留既有整理与来源错误状态，事件本身不触发媒体或仓库删除

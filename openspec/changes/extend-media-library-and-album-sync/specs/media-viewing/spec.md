# Spec Delta

## Purpose

在 Windows 与 iOS 上提供完整的媒体查看体验，让静态照片能够全屏展示、实况照片和独立视频能够播放动态画面及声音，并使新增查看入口始终服从既有隐私范围和访问控制。

## ADDED Requirements

### Requirement: 仓库封面由真实资源生成且服从查看撤销
Windows MUST 经认证解密与实际解码生成仓库媒体封面，并仅在加密索引中持久化；图片及实况使用静态资源，视频使用真实画面。完整查看器优先于封面，锁定或换库撤销旧请求。

#### Scenario: 浏览仅有仓库副本的媒体
- **WHEN** 用户浏览没有本地原文件及有效封面的项目
- **THEN** 串行读取真实资源生成封面，单次处理最多45秒和64 MiB认证块读取，持久化PNG最多256 KiB
- **AND** 失败准确显示不可用并允许重读，不使用模拟封面，不将封面视为完整备份证据

#### Scenario: 封面读取期间打开查看器或锁定
- **WHEN** 完整查看器打开、应用锁定或切换仓库
- **THEN** 撤销活动及排队的旧封面请求；完整查看器关闭后仅在有效新会话中恢复读取
- **AND** 不展示旧权限回调，不写出内部明文媒体临时文件

### Requirement: Windows 按 WRP-1 使用受控本机资源播放
Windows 客户端 SHALL 按已批准 WRP-1 B，在当前查看会话内通过随机认证的 IPv4 回环 HTTP 单范围读取提供仓库媒体，逐块认证解密后输出，不写内部明文缓存；只接受当前精确资源，关闭外部引用和播放器磁盘缓存，不将回环认证发给外网代理。

#### Scenario: 旧会话或非法回环请求
- **WHEN** 查看退出、应用锁定或请求认证、Host、路径、方法及 Range 不满足约束
- **THEN** 对应请求不能取得新的媒体明文，旧服务停止或拒绝请求
- **AND** 不因后台同步仍运行而保留查看授权

#### Scenario: 仓库删除后使用旧副本记录
- **WHEN** 当前认证清单已删除媒体而本机尚留旧 receipt
- **THEN** 新播放及导出必须拒绝将旧历史对象当作当前有效媒体
- **AND** 随机播放成功只证明已读取块，不记为完整备份校验

### Requirement: 照片全屏查看

应用 SHALL 在 Windows 和 iOS 提供照片全屏查看及退出入口；全屏查看与“查看详情”共同遵守当前媒体访问条件，不能通过打开查看器访问当前来源视图无权展示的媒体。

#### Scenario: 从普通浏览进入全屏
- **WHEN** 已解锁用户在普通浏览模式打开一张当前可见照片
- **THEN** 应用以全屏查看界面展示照片
- **AND** 用户可以退出并返回来源视图

#### Scenario: 从相册查看聚合视图隐藏项目
- **WHEN** 用户从所属相册打开一个在聚合视图隐藏的项目
- **THEN** 应用允许按该相册的可见范围查看
- **AND** 从“所有照片”或“我的收藏”进入的查看过程不额外引入隐藏项目

### Requirement: 实况照片双端有声播放

应用 SHALL 在 Windows 和 iOS 将 Live Photo 显示为一个带实况标识的媒体项目，列表展示静态封面，查看时提供动态画面和声音播放、暂停及声音控制。

#### Scenario: Windows 播放完整实况照片
- **WHEN** Windows 用户打开包含完整静态图和配对视频的 Live Photo 并开始播放
- **THEN** 应用播放配对视频的动态画面及其声音
- **AND** 仍将静态图和配对视频作为同一媒体管理项目

#### Scenario: iOS 播放并暂停实况照片
- **WHEN** iOS 用户开始并暂停 Live Photo 播放
- **THEN** 动态画面及声音按照播放控制响应
- **AND** 用户能够控制声音，不需要把配对视频导出为另一项目才能观看

#### Scenario: 实况资源不完整
- **WHEN** 应用无法取得某个 Live Photo 的配对资源
- **THEN** 应用明确报告动态内容暂不可播放或资源不完整
- **AND** 只显示静态封面不能被视为完整实况播放成功

### Requirement: 独立视频播放控制

应用 SHALL 在两个客户端播放独立视频，并提供全屏查看、播放／暂停、进度跳转和声音控制；列表提供视频类型标识、封面及可取得的时长。

#### Scenario: 播放并定位视频
- **WHEN** 用户打开可访问的视频并调整播放进度
- **THEN** 应用在所选位置继续播放画面与声音
- **AND** 暂停和声音控制可正常使用

### Requirement: iPhone 来源视频兼容范围

应用 SHALL 支持 iPhone 普通录像的 H.264、HEVC 和 iPhone 录制的 ProRes 视频，以及从短视频平台保存到 iPhone 的常见本地视频；Windows 与 iOS 均需通过对应真实样本的画面、声音和播放控制验证。

#### Scenario: 两端播放 ProRes
- **WHEN** 用户在任一客户端打开纳入验收样本范围的 iPhone ProRes 录像
- **THEN** 应用能够播放画面和声音，并执行视频播放控制
- **AND** 只完成导入、同步或显示封面不能算作 ProRes 支持完成

#### Scenario: 播放平台保存到本机的视频
- **WHEN** 用户导入从短视频平台保存到 iPhone、属于已验证兼容范围的本地视频
- **THEN** 用户可以在两个客户端中观看
- **AND** 此功能不要求登录短视频平台或新增平台下载功能

#### Scenario: 文件损坏或尚不兼容
- **WHEN** 导入的视频损坏或实际编码不在已验证的播放能力内
- **THEN** 应用提供准确的失败原因，不显示虚假的播放成功状态
- **AND** 不为掩盖播放失败而擅自覆盖或删除原文件

### Requirement: 锁定立即阻断媒体观看

应用 SHALL 在普通应用锁上锁或三天照片密码验证到期时停止媒体画面和声音播放，关闭可访问媒体内容的查看界面，仅显示现有密码界面；同步阻断继续遵守现有三天验证规则。

#### Scenario: 正在播放时上锁
- **WHEN** 普通应用锁生效且视频或 Live Photo 正在播放
- **THEN** 画面和声音停止，媒体查看界面被密码界面替换
- **AND** 返回或旧播放回调不能恢复内容访问

#### Scenario: 三天到期时正在全屏播放
- **WHEN** 照片密码验证到期且用户正在全屏观看媒体
- **THEN** 查看和播放被阻断，同步暂停
- **AND** 错误照片密码或仅正确 PIN 不能恢复观看或同步

### Requirement: 播放能力由真实资源验证
应用 SHALL 使用实际媒体资源提供查看及播放，不用预置画面、模拟播放状态或静态封面冒充动态成功；已确认双端格式须以对应原始来源样本验证音画和控制。

#### Scenario: 必需格式在目标端失败
- **WHEN** 纳入首版的 ProRes 或其他必需媒体在某目标端无法正常播放
- **THEN** 应用准确报错且该格式的正式支持仍为未完成
- **AND** 不通过删除验收样本、降质覆盖原资源或显示封面将结果改成通过

### Requirement: 解密媒体资源服从访问与暂存保护
应用 SHALL 在通过解密完整性检查后才向查看器提供可用资源，按批准隐私方案处理播放所需缓存及暂存；锁定时停止音画及内容访问，旧异步结果不得重新开放资源。

#### Scenario: 恢复媒体播放期间上锁
- **WHEN** 来自仓库解密的媒体正在播放而普通应用锁或到期限制生效
- **THEN** 实际画面和声音停止，旧资源会话失效
- **AND** 缓存及暂存按批准生命周期保护，不仅在界面覆盖一层锁屏

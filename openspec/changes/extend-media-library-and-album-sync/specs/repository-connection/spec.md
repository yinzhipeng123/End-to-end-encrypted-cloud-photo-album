# Spec Delta

## ADDED Requirements

### Requirement: Windows 自动使用已配置的 HTTP 代理
Windows 客户端 SHALL 在每次网络请求前检测启动环境中的 HTTPS_PROXY／HTTP_PROXY／ALL_PROXY（兼容小写）及当前用户的 Windows 系统手动代理，显式环境变量优先；适用的 NO_PROXY 和系统例外按目标主机匹配。代理配置无效、连接失败或暂不支持时不得伪造成功或静默改用直连；保持 GitHub 目标白名单、TLS 验证、强制安全锁取消和端到端加密要求。界面显示检测到的来源及不含凭据的地址。

#### Scenario: 从桌面启动且系统代理已启用
- **WHEN** 应用没有继承命令行代理变量，Windows 当前用户配置 HTTP 代理
- **THEN** 授权、仓库查询、初始化及密文传输共用检测到的系统代理
- **AND** 下一次请求重新读取系统代理，用户不必用命令行启动应用

#### Scenario: HTTP 与 SOCKS 环境变量同时存在
- **WHEN** HTTPS_PROXY 指向 HTTP 代理，同时 ALL_PROXY 指向 SOCKS5
- **THEN** HTTPS 请求优先使用 HTTPS_PROXY 指定的 HTTP 代理
- **AND** 不删除 SOCKS 协议前缀后将其当作 HTTP；仅 SOCKS、PAC／WPAD、HTTPS 代理服务器及带凭据的代理地址尚未支持时明确报错

#### Scenario: 代理失败或后台会话撤销
- **WHEN** 代理拒绝连接、超时、TLS 握手失败或强制安全锁撤销后台会话
- **THEN** 显示相应失败或取消状态，不标初始化或备份完成
- **AND** 取消在途连接，不发送直连回退请求，不在日志或界面回显代理凭据

### Requirement: 空仓库初始化须明确且有界
Windows GitHub客户端 SHALL 按已批准TD09-I提供明确初始化操作，重新核对私有目标和权限；空库只在默认分支创建固定应用标识文件后建立epa-data-v1分支，恢复材料和密文只发布到数据分支。既有未知库、路径或分支保护不自动覆盖或放宽。

#### Scenario: 初始化中断
- **WHEN** 标识文件已创建但数据分支或认证根尚未完成
- **THEN** 显示实际未完成状态并在重启后核对接续
- **AND** 不宣称备份就绪，不覆盖其它内容或生成用户媒体明文

### Requirement: GitHub 使用批准的细权限授权方案
应用 SHALL 按 GAR-2 TD08-A 使用私有 GitHub App、指定照片仓库安装、Contents 读写与 Metadata 只读权限及 Device Flow 用户令牌；客户端不持有应用私钥或共享 Client Secret。用户令牌保护、刷新和取消按批准方案实施，平台注册完成不等于用户已授权或仓库可用。

#### Scenario: 目标不在可访问安装范围
- **WHEN** 用户已完成设备授权但目标私有仓库未安装该应用，或不具备所需写权限
- **THEN** 客户端依据真实安装和仓库查询结果阻断该目标
- **AND** 不请求更宽权限或换用源码仓库凭据来伪造可用状态

#### Scenario: 刷新材料无法安全接续
- **WHEN** 刷新失败、响应丢失或新令牌对不能完成受保护保存
- **THEN** 应用准确阻断访问并按 GAR-2 要求重新授权
- **AND** 不将平台重新授权作为照片密码验证或解除本机锁定

#### Scenario: 已注册但尚未安装到仓库
- **WHEN** 设备授权成功且实际安装查询未返回符合该 App 和本人账号的安装
- **THEN** 应用可以保存真实账号连接，明确提示未查到符合条件的安装且不显示同步就绪
- **AND** 用户稍后安装后可再次检查连接，客户端不自动安装或选择源码仓库

#### Scenario: 没有可选仓库时仍可找到安装入口
- **WHEN** 用户打开云端同步页面，尚未授权、尚未核验或仓库查询结果为空
- **THEN** 选择仓库区域仍显示真实状态，并提供安装管理与刷新入口
- **AND** 安装管理仅打开固定 GitHub 官方页面并说明本应用身份，由用户在 GitHub 选择安装仓库；不把打开浏览器当作安装成功

#### Scenario: 锁定取消授权或查询
- **WHEN** 应用锁定、会话到期或用户取消本次操作
- **THEN** 客户端停止轮询并取消在途请求，拒绝迟到响应建立连接或覆盖目标
- **AND** 取消前已实际提交的加密记录按真实状态保留，取消提示不虚构回滚

#### Scenario: 设备码响应或开始轮询发生延迟
- **WHEN** 设备码响应缓慢或界面稍后才开始轮询
- **THEN** 本地有效期使用绑定此次设备码的单调计时，并保守计入申请请求耗时，不在每次轮询入口重新计时
- **AND** 期限已过则不发送下一次令牌请求，迟到成功响应也不能建立连接；界面有效期取同一剩余时长

#### Scenario: 平台返回无效设备码或邮箱未验证
- **WHEN** 平台返回 incorrect_device_code、bad_verification_code 或 unverified_user_email
- **THEN** 应用给出重新申请设备码或先在GitHub验证主邮箱的明确提示，清除本次设备码显示并允许重试
- **AND** 不把错误响应保存成新账号连接或令牌，不回显平台原始响应中的秘密

#### Scenario: 请求得到未被允许的成功状态码
- **WHEN** 平台返回2xx，但不属于该具体请求所允许的状态码
- **THEN** 客户端拒绝该异常响应，不以笼统HTTP成功代替所需业务结果

### Requirement: Gitee 授权无需自建服务
应用 SHALL 在无需用户自建授权服务的前提下实现 Gitee 授权；客户端包不得内置需要保密的共享 Client Secret，不能以 PAT 或平台密码输入冒充已确认的授权登录。

#### Scenario: 公开客户端能力尚未确认
- **WHEN** 尚未取得符合上述约束的 Gitee 流程及实际验证证据
- **THEN** 应用明确显示该能力未实现并禁用执行入口
- **AND** 保留 Gitee 产品需求，不暗中新增授权中介服务或伪造成功

### Requirement: 授权结果经真实平台验证
应用 SHALL 分别使用经批准的 GitHub 和 Gitee 授权流程，依据真实平台响应建立账号访问状态，不以界面变量、预设令牌或固定仓库列表作为授权完成依据。

#### Scenario: 用户完成平台授权
- **WHEN** 用户通过所选平台的实际授权流程并取得有效访问结果
- **THEN** 应用确认真实账号及获准访问能力后建立连接状态
- **AND** 不将平台授权作为照片解密成功

#### Scenario: 授权拒绝或校验失败
- **WHEN** 用户取消、平台拒绝，或授权响应不符合批准的校验条件
- **THEN** 应用保持未连接或准确失败状态
- **AND** 不载入演示账号或虚构成功结果

### Requirement: 实际私有仓库与权限核对
应用 SHALL 从平台查询用户实际可访问的仓库，核对所选目标的私有属性、身份和操作所需权限并保存配置；不得自动把公共或不可写目标视为合格同步位置。

#### Scenario: 选择可用私有仓库
- **WHEN** 用户选择平台实际返回且满足所需访问条件的私有仓库
- **THEN** 应用保存该目标的真实身份并据此执行后续请求
- **AND** 不因目标名称与其他仓库相同而混用副本状态

#### Scenario: 目标权限或可见性变化
- **WHEN** 已选目标不再满足私有属性或操作权限
- **THEN** 应用核对并阻断受影响操作，准确显示原因
- **AND** 不报告尚未完成的读写已经成功

### Requirement: 授权材料受保护且结果可恢复
应用 SHALL 按批准的凭据保护方案保存所需授权材料及目标配置，真实处理过期、撤销、重新授权和重启；日志、普通索引与客户端包不得含需要保密的原始授权秘密。

#### Scenario: 重启或授权撤销
- **WHEN** 客户端重启使用已有授权材料，或平台撤销访问
- **THEN** 应用按实际有效性及批准策略继续访问或要求重新授权
- **AND** 不回退演示授权，不用平台重新授权解除照片密码到期限制

#### Scenario: 刷新请求中断后重启
- **WHEN** 本机已持久化令牌刷新意图，但新令牌对没有完整密封并提交当前引用
- **THEN** 客户端要求重新授权，不重用可能已失效的旧令牌对
- **AND** 不用其他账号、安装或本机实例的密封材料作为回退

#### Scenario: 断开本机连接
- **WHEN** 用户选择断开本机连接
- **THEN** 应用先使本机引用不可用，再移除当前密封令牌并保存断开状态
- **AND** 明确 GitHub 平台授权未因此撤销，平台撤销须由用户在官方设置执行

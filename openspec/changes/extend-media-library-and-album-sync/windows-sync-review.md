## TD10-S — Ciphertext and Recovery Format

### Limits and Identifiers

- `MB` 明确为十进制 1,000,000 字节；仓库任一应用二进制对象硬上限 50,000,000 字节。v1 采用更小的固定明文块上限 4,194,304 字节（4 MiB），不按媒体类型改变，不对照片库总量设配额。
- 块为 `EPABLK01`（8 字节 ASCII）＋24 字节随机 nonce＋XChaCha20-Poly1305 密文及16字节标签，总开销48字节。满块为4,194,352字节；Base64 为5,592,472字节，JSON封装另计。
- 每个资源版本使用已有用途1包装的独立随机32字节资源密钥。每次实际加密生成新nonce；重传只复用已保存的相同密文，不对不同明文重用nonce。
- vault／media／revision／resource／opaque object ID 均为16字节随机值；文本采用32个小写十六进制字符。版本ID不由文件名、时间或明文指纹推导。
- 对象位于 `.encrypted-photo-app/v1/objects/<ID前两位>/<ID>.bin`；固定入口仅 `recovery.bin` 与 `head.bin`。文件路径不含原文件名、设备路径或媒体类别。Git树／blob SHA仅定位，不代替AEAD。

### Authentication and Manifests

- 复用 `VaultCredentialSession.createResource/openResource` 与 `encryptRecoveryMetadata/decryptRecoveryMetadata`。资源context为ASCII `EPA/resource/v1\0`＋mediaId＋revisionId＋resourceId；单元context为ASCII `EPA/chunk/v1\0`＋索引u64LE＋块总数u64LE＋原资源总长度u64LE＋本块明文长度u32LE。已有 `_mediaAad` 进一步绑定库ID、用途及context长度。
- 加密元数据外壳 `EPAMET01`＋nonce24＋密文（含标签16）；最多1,048,576字节明文。metadata context为ASCII `EPA/metadata/v1\0`＋对象用途标签（root/index/media/resource/page）＋该对象ID；固定head使用全零对象ID。不得互换媒体、页面和库。
- 元数据为严格UTF-8规范JSON：键按Unicode码点排序、无额外空白／重复键，整数计数使用无前导零十进制字符串，不接收浮点、负值或未知必需版本。解码后重新规范编码须等于原始字节，避免重复键／多义表示。解析先校验外壳、大小、版本及有界字段，后做密码学工作；长度与索引求和检查溢出。
- 根清单包含库ID、协议版本、提交序号、前一根的密文摘要、恢复材料摘要及媒体索引首页引用。引用包含opaque ID、Git blob SHA、BLAKE2b-256密文摘要及实际长度。恢复材料摘要绑定完整recovery.bin。
- 媒体索引按随机mediaId排序分页，每页最多256项，包含下一页的完整认证引用；尾页明确null。根记录项目数／页数；拒绝环、重复ID、错序、数量不符、缺页或截断。处理分页写入SQLCipher，不把全库放内存。页数不是总容量限制。
- 每个媒体描述包含mediaId、revisionId、父版本ID、类型、原始文件名、实际可得属性、必要资源集合和Live Photo可靠配对资料。资源描述包含角色、resourceId、原始长度、完整BLAKE2b-256明文摘要、资源密钥包装及块清单首页；块清单同样最多256项／页并认证下一页，记录索引／明文长度／密文引用。不得以同名推测实况配对，不以封面替代原视频。
- 同一资源的块数、顺序、各块长度、总字节数及完整内容摘要全部核对；Live Photo只有全部必要资源验证后才标完整。0字节媒体不进入完整备份状态，显示来源无有效内容。
- 用户文件名、摘要、媒体关系、资源顺序和属性只在加密清单内；不上传本机来源路径、相册／收藏／隐藏配置、SQLCipher目录、PIN、DPAPI材料或OAuth令牌。平台仍可观察仓库身份、随机对象关联、数量、长度、提交时间及访问流量；不加入填充或承诺隐藏流量。
- 不使用压缩或有损转码，不改变原字节。未知格式拒绝处理并保留旧数据，不自动迁移、降级、重加密或重置。

### Password Recovery Material

建议复用已验证的本机主密钥包装投影，避免为首次备份额外缓存用户密码，也不上传整个bootstrap或本机目录密钥：

1. `recovery.bin` 精确188字节：`EPAREC01`（8）＋当前 `VaultBootstrapRecord` 的前180字节（132字节原认证头＋48字节主密钥包装）。最后48字节本机目录密钥包装**不包含**。
2. 内层保留原magic、固定KDF参数、包装代次、随机库／目录ID、盐和nonce；其中随机本机目录ID／目录nonce是原主包装AAD的一部分，因此作为不具名随机字段保留。它们不提供本机目录解密密钥。
3. 用独立严格解析器检查188字节及投影参数，不能将短投影冒充228字节本机bootstrap。主包装AAD保持现有 `EPA/bootstrap/master/v1\0`＋原132字节头，先固定参数校验，再真实Argon2id和AEAD。
4. 恢复者仅需平台访问权与正确照片密码，从远端得到原主密钥。新设备生成自己随机的目录密钥／目录ID、PIN、安装及DPAPI材料；用已认证密码建立本机bootstrap，不复用发送端catalog密钥，不复制其PIN或72小时期限。
5. 初次选择已有库必须确认库身份，禁止把不同vaultId的本机库与远端库自动合并或覆盖。恢复到新专用目录，失败保留已有目录；独立恢复UI不默默取代当前库。
6. 修改密码继续重新包装同一主密钥。已关联远端时，在本地新包装保存前持久化待发布意图；将新投影、认证新根作为一次提交发布并读回，分别显示本机完成／仓库待更新。未完成时不宣称全端成功；重启接续不保存密码。其它设备发现投影摘要或代次变化，撤销旧辅助会话并要求当前仓库照片密码。
7. 并发改密比较共同基线的恢复摘要，不依靠数字代次相同判相同密码；不同投影冲突停止自动发布，保留两端材料，要求用户以当前远端密码重新认证后再明确处理。不能默选较大的代次、覆盖另一端包装或用PIN完成改密。
8. 新投影不会使历史投影、旧密码或已经复制的主密钥失效；不改写历史，不承诺远程即时撤销。无可信先前状态的新设备不能证明平台返回的是最新快照。

## TD11-S — Identity, Publication and Restart

- 保留已批准的本机媒体ID；新导入的独立副本分别管理。远端恢复沿用远端mediaId，记录来源为远端；不按相同原文件名／字节自动合并另一台设备独立导入的文件。明文指纹仅用于认证内容和判定同一项目版本，不公开或用来派生密钥。
- 传输键绑定provider、repositoryId、vaultId、mediaId、revisionId；目标切换使旧请求失效，绝不继承其他仓库完成状态。安装ID／账号单独绑定授权材料，不把账号改名误当新仓库。
- 本机任务保存基线根／提交、媒体版本、资源集合、已经加密的对象及上传／读回确认点、候选提交、结果未知状态；全部进SQLCipher。批量与自动入口共用相同幂等键，真实字节计数区分读取、上传、校验和已发布。
- 先按WIR-1稳定句柄将一个完整资源加密落盘并核对内容指纹，释放源文件后才上传；不在等待网络时长期阻止用户操作原文件。暂存是已加密字节，文件变化不会混入本次版本；新版本另排队。
- GitHub顺序：逐对象POST blob → GET blob读回，核对长度／密文摘要／AEAD及恢复字节摘要 → 构造包含全部资源和认证清单的tree → 单父commit → 对 `refs/heads/epa-data-v1` 执行 `force=false` 更新 → 读回该提交及根和资源引用。全部通过后才写入本机“已备份”。Git对象哈希不是认证证明。
- 索引采用不可变链页，更新时自尾向前生成受影响页；初版以清楚的完整性和可恢复性为先，最坏更新成本随索引页数增长。每次发布最多聚合20项已完整验证媒体；不足20项不等待凑批。对象和页有界，外部限流如实暂停，不以无限容量承诺掩盖成本。
- 不递归读取不受限Git tree；按需要逐层读取，truncated一律不能视为完整结果。未识别的命名空间或根字段停止写入；其它分支／目录保留。
- 引用更新不是严格CAS。出现409／422时重新读取实际头，并验证根／恢复材料。不同媒体的新增可合并；同媒体相同版本只复用；同媒体不同内容均保留为冲突版本并阻断该项目自动选主，不静默覆盖、不自动增删用户文件。无冲突项目可继续。
- 未知网络结果先核对候选提交是否已成为当前头或已被当前头包含，及当前认证索引是否保留目标版本；不能因上次请求超时直接生成第二次完成。未引用对象不能当备份，不自动清理悬挂对象。
- 本机保存最近确认根及提交；后续返回不包含已知历史的头或回退根时停止并报告，无法核验同样停止，不强推修复。不声称可防恶意平台对新设备完整回放。
- 外部原文件消失仍保留已验证远端副本，隐藏／收藏不改变备份意图。已存在“不自动重传”本机意图继续阻断自动队列，显式上传才解除指定项目意图。**远端墓碑格式和真实删除仍等TD14**，遇到未知删除版本停止处理；4.7／7.x不能据上传成功整体勾选。

## TD13-S and TD12-S — Execution and Resource Bounds

- 已选择且验证通过的目标在App已解锁、密码未到期、未手动暂停时自动处理新增／既有待上传版本；使用系统当前可用网络，不自动更改系统代理，不增加Wi-Fi专属设置或后台服务。网络断开是可恢复阻断，退出／最小化／系统锁定／挂起严格按SFR-1停止。
- 一个活动媒体传输任务、一个HTTP请求；复用WIR-1源文件读取协调，导入和上传不同时持有内容读取配额。队列按100条加载，实际数据块4MiB；加密资源工作集目标不超过128MiB，验收测量增量峰值（含JSON/Base64、原生加密缓冲），超预算先修复，不静默调大。
- 密文待上传暂存预算默认512MiB，数据目的地可用空间必须额外保留256MiB。大于预算的单个资源按“稳定句柄加密一段、释放后再核对完整版本”不能保证同版，因此**不采用这种回退**：大资源允许专属暂存超过512MiB，但预留完整密文大小＋256MiB后才开始，最多一个大资源，空间不足暂停且原文件不变。完整资源加密后才释放句柄、执行网络。这项例外需随本稿明确批准，不等于照片库容量上限。
- 暂存放当前数据目录私有ACL下，用随机文件名；映射／断点只进SQLCipher。写.part、flush、关闭、验证、改名后提交记录；中断不把半文件当完成。锁定撤销工作和可控明文／密钥缓冲，磁盘仅留密文供下次核对；保留队列引用的暂存，不自动删用户文件。
- 传输暂存与按需下载缓存分开记账。下载缓存密文上限512MiB，按最近使用淘汰未被活动读取／任务引用的块；超大资源按块流式读取，不要求全量下载。缓存缺失重下，不影响备份身份。
- 连接超时20秒；普通元数据请求45秒；blob请求无数据30秒或总计5分钟超时；连接取消尽力关闭socket，结果未知进加密队列，下次满足门禁后核对。串行写请求间隔至少1秒，且每小时最多400次写请求（包含blob/tree/commit/ref）；实测更严限制按平台响应暂停。
- 暂时网络／5xx重试5／15／60秒，此后每5分钟，添加0–20%随机延迟，期限加密保存；429／带限流403取Retry-After或reset与本机退避中的较晚值。401按GAR-2刷新／重新授权；权限、非私有、额度、格式或认证错误不得无限重试，保留原因等待修复。
- 用户暂停保存为独立原因。PIN／照片密码验证仅解除相应门禁，不能解除手动暂停。锁定立即禁止新请求／新加密及成功落库，尽力取消已发请求；已到服务端的字节不能撤回。
- 按需读取先认证清单、所需完整密文块，再将该块明文交给受控读取者；单个块必须完整认证后才输出。完整恢复还须检查全部资源字节数和摘要后才称成功。缓存不保存明文；锁定使旧读取句柄及回调失效。
- 此受控读取接口可以服务图片、视频和实况，但不自动批准localhost明文HTTP服务器、播放器明文临时文件或另一个播放后端。media_kit能否接受接口需继续验证，4.6完整播放接线不能提前勾选。普通文件导出及同名冲突仍按TD12后续确认。

## TD09-I — Empty Repository Initialization

建议增加一个明确的“初始化此私有仓库”操作，显示目标owner/name和实际将写入的位置，不把选择仓库等同于已初始化。

1. 重新验证仓库ID、private、安装与写权限，检查数据分支／应用入口；已有其它库或未知格式不得覆盖。

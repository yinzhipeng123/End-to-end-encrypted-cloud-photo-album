# Acceptance

## Scope and Evidence Rules

2026-11-09 后续用户明确本轮仅开发并运行 Windows、保留 iOS 需求：本矩阵中 Windows 组合先执行，iOS／Windows↔iOS 组合标记暂缓未验证，不阻塞 Windows 实施；原门槛不删除，不以 Windows 证据代替 iOS。任务分拆见 windows-delivery.md 与 tasks.md。

2026-11-09：本文件定义获用户批准方向下的正式产品验收标准，**不是执行报告**。下表所有正式验收均为“未执行／未完成”；旧人工样本、内存规则测试和隔离探针只在 implementation-status.md 作为历史局部证据引用。规格中的 SHALL/MUST 不因缺环境、账号或设备而降低。

每条正式验收须记录：AC ID、对应规格 Requirement/Scenario、任务编号、代码提交或工作区摘要、构建版本及哈希、平台／OS／设备、依赖和数据格式版本、输入样本及来源、步骤、预期、实际副作用、失败／重启结果、证据位置、执行时间、结论。不得记录真实密码、令牌、密钥或用户私有媒体。多平台／多供应商分别记录通过，某一组合通过不替其他组合。

人工文件允许在隔离测试中执行真实读写／加密／平台请求；单元测试可使用替身验证规则，但不能代替集成验收。iPhone 来源格式必须包括实际来源样本，不能只用生成视频替代。只看扩展名、封面或布尔状态不构成格式／备份成功。

## Release Gate

界面完成、规则完成、模拟完成和局部真实能力分别描述，不能按复用代码行数折算正式验收。正式完成要求所有已确认必需场景通过；缺设备、账号、待批准方案或 ProRes 失败都保留明确未完成。SFR-1 的 TD01–TD06 已明确批准，AC02–05 的参数、密码／PIN、锁定、期限和失败标准据此执行；文档格式验证与运行验证分开报告，每次真实结果另行留证，不把本矩阵改成预填通过。

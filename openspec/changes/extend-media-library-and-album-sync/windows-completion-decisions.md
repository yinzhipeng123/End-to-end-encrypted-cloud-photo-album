# Windows 后续编码决策（2026-11-11）

依据用户最新明确授权“我默认都批准，先不要问我，先把所有的编码任务都完成”，本文件记录剩余 Windows 技术选择，替代此前逐项提问流程。代码仍需用户统一验收，不能勾选未验收任务；iOS 暂缓，Gitee 的平台能力缺口不能用默认批准创造出来。

## TD12-W：导出

- 用户选择目标文件夹，每个媒体创建随机标识的独立导出子目录，原文件名安全化后保留；不覆盖既有文件。相比覆盖旧文件，可减少误操作和中断风险；代价是多一层目录。
- 本地使用稳定文件句柄完整核对原版本；远端逐块认证解密并检查完整资源摘要。输出完成后重新读取输出文件核对大小和摘要，才从 `.partial` 改为最终名称。
- 明文仅写到用户明确选择的导出目录，不写程序内部临时目录。多资源媒体全部校验后发布；取消清理本次未完成文件，已发布部分保留且准确报告不完整。进程强制中断可能留下用户导出目录中的 `.partial`，加密任务记录保留位置，不冒称跨文件原子提交。

## TD14-W：删除与异常接续

- Windows 本地删除采用可恢复的同卷移动：原文件移入来源根目录下专用 `.epa-recycle`，保留原字节；原路径确实消失，不永久擦除，也不声称进入 Windows 系统回收站。该目录不被自动导入。加密数据库保存原路径、回收位置、版本及操作状态。优点是避免系统回收站不可用时永久删除，代价是暂不释放磁盘容量。
- 移动必须持有同一个已经完整验证内容的原生句柄，目标不覆盖、同卷、祖先无重解析点；失败不回退为永久删除。中断按持久化意图及原／目标实际状态核对；内容已变化则保留并报冲突。
- “删除本地、保留仓库”先实际下载认证并完整校验当前版本仓库副本；没有可恢复当前副本则拒绝本地移除。“删除仓库、保留本地”核对本地完整当前版本后发布仓库删除。“同步删除”保留本地可恢复移动记录，并发布持久化删除标记。
- 远端删除删除当前清单的有效版本及其当前树中的资源路径，保留认证删除标记；Git 历史可能保留密文，不强推、不重写历史、不承诺安全擦除或立即减少仓库空间。
- 删除标记绑定媒体 ID、被删版本、唯一操作 ID、范围。离线客户端重连核对后只处理完全匹配版本；本地已修改的版本保留并报告冲突，不自动删新内容。单机完成不声称所有离线设备已处理。
- 逐目标状态加密持久化；本地／仓库部分失败保留已完成结果，重试核对而不重复破坏。仅删仓库后抑制自动重传；显式上传生成新发布代次并解除抑制。

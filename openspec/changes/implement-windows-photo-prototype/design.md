# Design

## Context

见 proposal.md。本机当前没有 Flutter 工程，原始规划的 18 项任务仍保留在归档中。本变更接续其中 Windows 原型部分，不修改归档历史；正式安全与存储决策仍参考归档设计 Q01–Q09。

## Goals / Non-Goals

**Goals:** 建立可运行的 Windows 原型，用确定性状态和行为测试证明交互规则，用户能直接查看并体验。

**Non-Goals:** 不声称实现安全存储、真实平台授权、原图访问、持久化密码或真实备份；不在本机代替 iOS 构建验收。

## Decisions

1. 使用 Flutter Material 组件、ChangeNotifier 和内存模型，无第三方运行时插件。原型不需要数据库或全局路由框架，后续正式架构另行选择。
2. UI 分为共享主题、可复用组件、页面及演示模型。桌面采用侧栏和照片网格，窄窗口采用抽屉；“密屿”仅为原型展示名，青绿色与浅暖灰为可调整的视觉建议。
3. 首次打开可直接体验虚构照片库，同时提供重新首次设置入口。演示密码在设置及验证页注明，不能输入真实密码。所有演示状态在退出进程后重置。
4. 仓库选择、导入、导出和删除只改变虚构会话；内置样片随应用打包，运行期间不请求远程照片。用户原目录始终不被访问。
5. 应用锁、照片库解锁和三天到期由独立状态控制。根界面在锁定时替换为密码页，包括关闭已经打开的详情/对话框，防止旧路由留在锁屏上方。仅照片密码成功重置周期。
6. 同步使用确定性阶段：排队、模拟加密、模拟分块、模拟上传、完成。到期阻断所有推进，恢复保留已有进度；网络/权限/容量异常独立于密码状态。
7. 原型普通应用锁对同步的行为可在演示设置中选择，默认继续仅为演示选项，不确定正式策略。删除后的自动重新上传/下载不在原型中推断；演示将该照片从队列移除，重置会话后恢复，不形成正式删除协议。
8. 三种删除有范围确认，模拟失败保持原状态，成功分别修改本地与远端状态；同步删除演示另一客户端响应。缓存清理不冒充原图删除，界面不承诺 Git 历史清除。
9. 时间可注入和推进，测试覆盖组合锁、误输密码、平台重新授权、队列暂停与恢复、删除结果、去重和失败重试；界面测试覆盖宽窄布局及锁屏替换。

## Risks / Trade-offs

- [内存密码比较被误用于生产] → 模型、UI 和 README 均标注演示用途，正式安全实现必须另建方案。
- [样片看起来像用户照片] → 明示内置演示库与来源，导入入口只导入内置样片。
- [构建环境需要管理员授权] → 安装官方签名构建工具，系统授权由用户完成。
- [跨平台 UI 被当成 iOS 完成] → 本次仅验收 Windows，单独保留 iOS 构建与真机工作。

## Migration Plan

不迁移生产数据；首次运行生成内存演示会话。关闭或重置演示即可恢复初始状态。Windows 可执行文件与启动脚本保留在本地，README 记录实际运行命令与验证结果。

## Open Questions

正式产品的 Q01–Q09 保留于归档设计，均不通过原型实现静默定案。视觉、页面名称与原型布局可根据用户体验反馈调整。

# Proposal

## Why

encrypted-photo-app 面向用户个人在 Windows 和 iPhone 之间管理照片：本地原照片可正常使用，远端副本在上传前经过客户端加密，并存入用户选择的 GitHub 或 Gitee 私有仓库。先完成需求与原型设计，再验证真实同步和安全能力，重点保证数据安全、稳定性和长期可维护性。

## What Changes

以下为 2026-11-06 探索中已确认的产品要求。本次更新只记录这些决定并消除旧草案冲突，不创建应用代码，也不把待定技术方案视为已通过。

- 客户端采用 Flutter + Dart，同时面向 Windows 桌面和 iOS；Windows 具备浏览、整理、导入、导出照片的使用需求。
- 支持 GitHub 和 Gitee 授权登录及私有仓库选择，应用自动同步照片；任何照片上传前都必须完成客户端加密。
- Windows 使用普通照片源目录并保留原图明文，远端保存加密副本；密文需要分块，目标尽量控制在每块 50 MB 以内。
- 应用不人为设置照片库总容量配额，同时识别外部存储平台限制，不承诺平台容量无限。
- 用户设置并记住照片解密密码，App 明确提醒；不要求用户手动设置或保管解密密钥。密码学内部仍需密钥，其生成、派生和保存机制待定。
- Windows、iOS 均提供四位数字应用锁；普通上锁状态仅展示密码输入界面。
- 从上次成功输入照片解密密码开始，每 3 天强制再次验证。到期后锁定照片访问并暂停同步；四位密码不能解除到期阻断。照片解密密码正确后重置周期并恢复受影响的访问和同步。
- 删除时提供三个选择：删除本地保留仓库副本、同步删除、删除仓库副本保留本地。本地删除指 Windows 原目录或 iPhone 系统相册中的原照片。
- 产品按不使用 iCloud 的前提设计，不接入 iCloud，也不加入相关界面说明。

页面导航、视觉风格、网络默认策略、恢复码、设备批准/撤销、删除前必须校验仓库等，尚未得到用户确认，不作为本次必做功能。具体未决项统一记录在 [design.md](design.md) 的 Open Questions 中。

## Capabilities

### New Capabilities

- `repository-connection`：GitHub/Gitee 授权、私有仓库选择和账号授权边界。
- `vault-onboarding`：用户设置并记忆照片解密密码的使用体验。
- `photo-library`：双端照片管理、原照片使用方式及三种删除范围。
- `encrypted-storage`：上传前加密、密文分块、容量要求和客户端解密。
- `backup-management`：自动同步、加密前置条件及到期暂停与恢复。
- `app-access-control`：四位数字应用锁和每 3 天照片解密密码强制验证。
- `device-recovery`：新设备连接已有照片库时，平台授权与照片解密的边界。

### Modified Capabilities

无。主规格目录尚为空；以上均为本变更中的待实施规格，不代表功能已经实现。

## Impact

- 更新现有提案、设计、任务和四份规格，补充仓库连接、密文存储及应用访问控制三份规格。
- 同步更新项目配置和 README，移除旧技术路线和把模拟恢复码当作必经步骤的要求。
- 保留原型阶段：这些规格描述目标产品行为，原型可以用明确标识的模拟来验证交互；模拟通过不等于真实安全或同步能力已经通过验证。
- 未决事项涉及真实加密、授权、密钥保存及同步删除，相关实现必须等待方案明确。文档齐全和格式校验通过不代表这些决策已经完成。

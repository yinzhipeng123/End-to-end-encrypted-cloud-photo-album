# Spec Delta

## Purpose

支持用户个人在 Windows 和 iPhone 上浏览、整理、导入和导出照片，并明确普通本地原图与仓库密文副本之间的关系，让每次删除操作都按照用户选择的范围作用于真实原照片。

## ADDED Requirements

### Requirement: 双端照片管理

应用 SHALL 在 Windows 和 iOS 客户端提供照片浏览、整理、导入和导出能力；具体导航、排序、编辑及媒体格式范围尚待确定。

#### Scenario: 在任一客户端管理照片
- **WHEN** 用户在已获访问权限的 Windows 或 iOS 客户端使用照片库
- **THEN** 用户能够浏览、整理照片，并使用导入和导出入口

### Requirement: Windows 保留普通原照片

应用 SHALL 允许 Windows 使用普通照片源目录，并在未选择删除原照片时保留其中的普通图片；上传前加密作用于远端副本，不要求将源目录改造成只能由 App 解锁的密文目录。

#### Scenario: 上传 Windows 原照片
- **WHEN** 应用处理源目录中的照片并完成加密同步
- **THEN** 源目录中的原照片仍以普通图片形式存在
- **AND** 仓库存储遵循 encrypted-storage 的密文要求

### Requirement: 三种删除选择

应用 SHALL 在删除操作中提供“删除本地，保留仓库副本”“同步删除”“删除仓库副本，保留本地”三个明确选项。

#### Scenario: 选择删除范围
- **WHEN** 用户发起照片删除操作
- **THEN** 应用提供三个删除范围选项
- **AND** 按用户实际选择执行，不把某一种范围默认为全部删除

### Requirement: 本地删除作用于原照片

应用 SHALL 将本地删除解释为删除 Windows 原照片目录或 iPhone 系统相册中的原照片，而非仅清理 App 自己的缓存或下载副本。

#### Scenario: Windows 本地删除完成
- **WHEN** 用户选择涉及本地删除的操作且 Windows 原照片删除成功
- **THEN** 对应原目录中的原文件被删除
- **AND** 仅清理 App 缓存不能被报告为该原照片已经删除

#### Scenario: iPhone 本地删除完成
- **WHEN** 用户选择涉及本地删除的操作且 iPhone 系统相册原照片删除成功
- **THEN** 对应系统相册原照片被删除
- **AND** 仅清理 App 缓存不能被报告为该原照片已经删除

### Requirement: 删除本地并保留仓库副本

应用 SHALL 在用户选择第一种删除方式时删除当前设备的本地原照片，保留对应仓库副本。

#### Scenario: 仅删除本地原图
- **WHEN** 用户选择“删除本地，保留仓库副本”并成功完成操作
- **THEN** 当前设备的原照片已删除
- **AND** 仓库副本仍保留

### Requirement: 同步删除照片

应用 SHALL 在用户选择第二种删除方式时，将本地原照片删除及仓库副本删除作为同一次同步删除操作的范围，并向参与该照片库同步的客户端传递该操作。

#### Scenario: 完成同步删除
- **WHEN** 用户选择“同步删除”且相关客户端和仓库均成功完成该操作
- **THEN** 该操作涉及的本地原照片及仓库副本均已删除

### Requirement: 删除仓库并保留本地原照片

应用 SHALL 在用户选择第三种删除方式时删除仓库副本，保留本地原照片。

#### Scenario: 仅删除远端副本
- **WHEN** 用户选择“删除仓库副本，保留本地”并成功完成操作
- **THEN** 对应仓库副本已删除
- **AND** 本地原照片仍保留
